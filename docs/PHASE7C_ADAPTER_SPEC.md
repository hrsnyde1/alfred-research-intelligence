## 2. Hermes intake, identity and source lifecycle (HP01–HP04, PR03)

Phase 7B source references are under `/home/alfred/.hermes/hermes-agent/`: `gateway/profile_routing.py:133–185`, `gateway/hooks.py:43–111`, and `plugins/platforms/photon/adapter.py:889–931`.

Verified raw input is NDJSON `{messageId, space:{id,type,phone}, sender:{id}, content:{type,...}, timestamp}`. It is not an authenticated Research envelope by itself. Hermes must supply/attest the authenticated platform principal, receiving profile, verified conversation scope and grant. Do not trust a caller's environment/role field or the adapter's sender fallback alone for privileged identity.

**Proposed host intake requirements (wire version and issuer still unallocated):**

| Required field / property | Binding rule |
|---|---|
| Event ID + receiving platform/profile + conversation ID | Stable authenticated source event; reject missing/ambiguous identity. Message ID alone is not globally unique. |
| Authenticated requester + permitted recipient + environment mapping reference | Derived from approved current host grants; resolve personal/company identity outside message/source text. Check on every later operation, not just intake. |
| Original objective + exactly one submitted locator/authorized file reference | Content is data; reject multiple sources and forged metadata before task/effect creation. |
| Original optional pin + authenticated acquisition result | Preserve who supplied the pin, actual resolved commit/version, raw/snapshot digest, retrieval time, acquisition restrictions and provenance. Never manufacture an all-zero/fixture digest for an unfetched URL. |
| Policy/version + deadline/budget/retry allowance | Director-approved configuration, immutable on replay; no extra authority requested by a model. |
| Stable intake ID + payload digest | Scope dedupe to issuer/platform/profile/conversation/event/environment; identical replay resumes, changed payload fails closed. Persist pending intake before acquisition/task creation. |

Existing ResearchRequest v1 requires a pinned SourceIdentity revision/digest. For the **smallest first canary**, require an owner-selected public GitHub full-commit reference, then a bounded authorized acquisition that records the actual digest before materializing ResearchRequest. Preserve a durable pending intake and acquisition receipt; create exactly one Research task and only then use existing task-bound ACK semantics. If acquisition blocks, report pending/blocked intake through the approved host contract without inventing a task or successful research. This pre-task lifecycle and acknowledgement correlation need Hermes owner approval. General unpinned URLs/files require a separately reviewed additive submission-versus-snapshot version; do not silently repin source.v1 or change packet histories.

Reuse the accepted request/task dedupe after pins are established; persist original host event and submitted/observed distinctions. The host adapter may hash the full trusted identity tuple into bounded internal IDs, but the exact encoding must be versioned and collision-tested before approval. Source content cannot choose route, environment, provider, profile or permissions.

## 3. Outbound messaging and recovery (HP05–HP08)

Verified existing sidecar wire: token-protected `POST /send` with `spaceId` and `text` returns `ok` and `messageId`; `GET /inbound` supplies events. Port 8789 was observed in Phase 7B, but active contract/version and Research permission still need confirmation. Do not read/copy the sidecar token or start another inbound consumer that steals messages from Hermes.

Proposed outbound logical request binds operation ID, notice type, task/intake correlation, environment, conversation, recipient, payload digest, current result/receipt references and policy revision. Initial ACK means durable acceptance only. Final text states exactly the observed research/Memory/HQ/export/Sync stages. Live notices must be a separately approved type; test Notice requires SIMULATED and must not be relabeled.

Required transport operations are logical **send, authenticated lookup, reconcile and currentness/cancellation**, not new claimed installed endpoints. Lookup must distinguish definite absence, accepted, delivered, rejected/failed and unknown. A returned SDK messageId proves neither exactly-once send nor independent delivery. Caller idempotency, lookup retention, message-ID scope and partial/chunk behavior are open contracts. With missing or ambiguous evidence, preserve pending state and do not blind-resend or assert DELIVERED. Hermes' existing ledger must not independently retry the same Research notice in parallel; agree one owner of retry and a correlated obligation.

Before preparing/sending an undelivered FINAL, revalidate promotion, retrieval grant, selected export/Sync attempt and relevant HQ state. Preserve immutable original/checkpoint results and record a corrected projection. Remote currentness cannot rely on holding the Mac fake's local flock over an HTTP request: Memory/transport owners must agree a lease/version-precondition or equivalent authoritative validation/cancellation window. Later failure/revocation/supersession overrides old success. Prepared stale notices remain withheld until an approved replacement/cancel contract exists; accepted ambiguity needs authoritative lookup; delivered history is never rewritten. A correction/update must have its own operation identity, explicit link to the original notice and separately approved wording/recipient scope. No such live correction operation is identified yet.
