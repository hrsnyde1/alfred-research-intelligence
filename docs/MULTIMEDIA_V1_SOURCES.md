# Multimedia Research V1 — source handlers (Milestone 2)

2026-10-16. Adds multimedia acquisition and extraction to the local Research pipeline (`alfred_research.local`). Standard library only: `pyproject.toml` still declares no dependencies. No Hermes, Photon, Memory or production change.

## Interface

`local/sources.py` defines `SourceHandler`. Each source family implements:

| Member | Purpose |
|---|---|
| `claims_url(url)` | Platform handlers claim their URLs before generic HTTPS fetching. |
| `acquire_url(url)` | Returns `(bytes, snapshot_name, provenance)`, read-only and without credentials. |
| `extract(data, filename)` | Returns an `Extraction` (evidence, limitations, flags, metadata, `basis`). It depends only on the snapshot bytes and name, because the independent verifier re-extracts the pinned snapshot in a separate process. |
| `snapshot_names` / `suffixes` / `max_bytes` | Dispatch for snapshots and owner files, plus size bounds. |

`basis` states what the evidence actually is, for example `pdf_text_layer`, `transcript_auto_generated` or `caption_metadata_only`. Reports print the handler, basis and key metadata for every source. `UnsupportedSource` can carry observed metadata, such as a YouTube title, which the report lists as "observed, not analyzed" and which never becomes evidence. The registry is `handlers()`. `extract()` keeps the verifier's original 3-tuple signature.

## Handlers

| Source | Handler | Evidence and citations | Honest limits |
|---|---|---|---|
| Web articles | `documents.ArticleHandler` | Visible block text; `html-lineN` locations. Prefers `<article>`/`<main>` and removes nav, footer, aside, cookie, share and similar regions. Keeps title, author, publication date, canonical URL and description. | No JavaScript rendering. Falls back to all visible text when cleanup over-removes. |
| PDF (URL or file, ≤20 MB) | `pdf.PDFHandler` | Text layer; `page-N[/block-M]` locations. Handles classic and object-stream objects, Flate/LZW/ASCIIHex/ASCII85 filters, ToUnicode CMaps, simple encodings and form XObjects. Keeps title, author, creation date and page count. | No OCR. Scanned/image-only PDFs are `unsupported`; pages without text are listed; undecodable fonts are omitted; encrypted PDFs are refused. |
| DOCX (URL or file, ≤20 MB) | `documents.DocxHandler` | Body paragraphs and table rows; `paragraph-N` and `table-T-row-R` locations; core title, author and dates. | Headers, footers, footnotes, comments and images are not extracted. DTD/entity XML is refused. Legacy `.doc` is unsupported. |
| TXT/MD/CSV/VTT/SRT | `documents.TextHandler` | Unchanged line-range extraction. VTT/SRT are labeled as an owner-supplied transcript. | UTF-8 only. |
| GitHub repositories | `platforms.GitHubHandler` | Unauthenticated read-only API: metadata, commit pinned to a full SHA, file tree, languages. Up to 30 prioritized files (README, license, manifests, docs, entry points, then shallow code; ≤200 KB each, ≤1.5 MB total) fetched from `raw.githubusercontent.com` at that SHA. Locations are `path#La-Lb`, `github-metadata` and `tree`. Dependency and executable flags are recorded. | Code is never executed, dependencies are never installed, nothing is merged. Partial snapshot; unread files are listed. Subject to the 60-request/hour unauthenticated API limit. |
| YouTube | `platforms.YouTubeHandler` | oEmbed and watch-page metadata. If a caption track returns text: timestamped `t=HH:MM:SS-HH:MM:SS` windows plus a separately labeled creator description. Creator captions are preferred over auto-generated ones. | Without accessible caption text the source is `unsupported`, with the observed title and channel recorded; nothing is inferred from the title. Auto-generated captions are flagged. Visuals are never claimed as watched. |
| Instagram posts/Reels | `platforms.InstagramHandler` | Caption from public page metadata (`caption-metadata`). | Basis `caption_metadata_only`: the media is not watched or transcribed. A login wall, private post, profile or story is `unsupported`. |

Questions without sources still use the Wikipedia discovery fallback.

## Known gaps and next steps

- **YouTube transcripts are mostly inaccessible** to a plain unauthenticated client today: the timedtext endpoint returns an empty body. Working around YouTube's anti-automation measures is out of scope. Options for the owner: approve a maintained transcript dependency or provider, or keep the supported path of submitting a transcript file (`.vtt`/`.srt`/`.txt`).
- **Instagram** usually gates captions behind login. Caption-only support works when the public page exposes `og:description`. Media transcription is not provided.
- The handlers already plug into the existing job pipeline through `acquire()`. This covers most of Milestone 3; what remains is message-level link/attachment detection. Milestone 4 (Hermes routing adapter) and Memory promotion are unchanged and remain blocked as described in `LOCAL_V1.md`.
