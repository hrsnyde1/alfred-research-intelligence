# V1 audit and resolved gaps

The Phase 1–6 implementation contains working offline contracts, tenant isolation, task persistence, accounting, source parsing, Director routing, verification binding, intelligence catalog and Memory simulations. The existing 347 Python tests pass. These modules intentionally reject live production/model execution: `research.provider` only supplies `SyntheticModelProvider`; `research.workflow._Runtime` enforces that exact type; research responses and intelligence records carry simulation-only markings. Source acquisition was fixture/user-supplied only. Reclassifying those artifacts as live would be incorrect.

Phase 7 and Linux staging contain proposed contracts, acceptance harnesses, Photon bridges and a disabled independent connector. Hermes intake has an explicit offline authority and refuses live attachment. Installed Research Photon is inactive and discovery failed. These do not provide a working Research submission interface and are not prerequisites for the local engine.

The minimal completed addition is `alfred_research.local`: CLI submission/tracking; real pinned HTTPS and owner-file acquisition; reuse of existing HTML/evidence extraction and specialty classification; configured Codex or explicitly extractive Research workers; a distinct verification process/model session; source-cited report synthesis; persistent stage history, snapshots, reports and candidates; fresh-process retrieval; and a callable Hermes seam. Synthetic components and production services are preserved. Real artifacts have their own local schema and provenance rather than reusing simulated receipts or authorities.

Read-only SSH inspection confirms the active authoritative service is `alfred-memory-v1.service`. The installed release retains generic Memory create/review/search and the Obsidian editor bridge but lacks the proposed Research extension. No Research endpoint, credentials, factual-attestation authority, or approval policy has been established. The local candidate adapter therefore validates packets and explicitly blocks external submission/promotion. It does not repurpose generic create, edit Memory storage, or write Obsidian exports.

Remaining external integrations: Memory-owned candidate/promotion/attestation interface and authorization; authenticated Hermes tool registration; optional production Research deployment. Capability limitations: Wikipedia-only automatic question discovery (network-dependent), no independent factual corroboration beyond source-support checks, no direct YouTube/PDF/Office provider installed, bounded extraction/model context. The CLI and real source-to-report flow work without these integrations. No commit, push, sudo change, or service activation was performed.
